⏱ Data Pipeline — Solving the 2-Day Transaction Lag
The Problem
Transaction withdrawal data has a 2-day lag. The most recent data available today was from 2 days ago — meaning we cannot use yesterday's actual withdrawal for today's model run.
The Solution — Hourly Cash Position
Cash position (current SGD balance) updates every hour. Consecutive snapshot differences give us implied withdrawals in real time — no transaction data needed.
Withdrawal(t) = Position(t-1) − Position(t)
① Pull hourly snapshots
Last 72 hours of cash position for all 350 ATMs (updated to the last hour)
② Derive withdrawals
Compute implied hourly withdrawals from position differences. Flag refill events (sudden jumps up) and exclude them.
③ Feed into models
Derived daily withdrawals replace missing transaction data for HW, XGBoost and Prophet as if they were real.
④ 7-day forecast
Use latest hourly position as baseline. Forecast depletion 7 days forward. D+1 and D+2 drive today's schedule.
